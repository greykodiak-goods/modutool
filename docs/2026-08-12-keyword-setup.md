# 키워드 세팅 — 어디에 무엇을 넣는가 (2026-08-12)

> 대표 지시: "키워드 세팅은 어떻게 해?"

`2026-08-12-search-visibility.md` v2의 후속. 일반론 말고 **우리 페이지 실제 상태를 열어보고** 쓴다.

---

## 0. 먼저 — "키워드를 등록하는 칸"은 없다

가장 흔한 오해부터 지운다.

> **`<meta name="keywords">` 태그는 구글이 오래전부터 무시한다.** 넣어도 효과가 없다.
> 그래서 우리 페이지에도 없고, **없는 게 맞다.** 추가하지 않는다.

키워드는 등록하는 게 아니라, **그 단어가 페이지의 어디에 실제로 쓰였는지**로 결정된다.
"세팅"이란 결국 **어디에 넣을지를 정하는 일**이다.

### 키워드가 정해지는 위치 — 영향력 순서

| 순위 | 위치 | 비중 | 우리 상태 |
|---|---|---|---|
| 1 | **`<title>`** | 가장 강하다 | ✅ 있음 |
| 2 | **`<h1>`** | 강하다 | ✅ 있음 |
| 3 | **첫 문단 100단어** | 강하다 + **AI 개요 인용의 결정 요인** | ✅ 있음 |
| 4 | `<h2>` 소제목 · FAQ 질문문 | 보조 키워드를 담는 자리 | ✅ 있음 |
| 5 | 구조화 데이터 (schema.org) | 리치 결과·AI 요약에 유리 | ⚠️ **부분** (아래) |
| 6 | URL slug | 약하다 | ✅ (영문, 바꾸지 않는다) |
| 7 | 이미지 `alt`, 내부링크 앵커 텍스트 | 약하다 | 미점검 |
| — | `<meta name="description">` | **랭킹 요인 아님.** 스니펫으로 보여 **클릭률**에 영향 | ✅ 있음 |

## 1. 우리 실제 상태 — `ko/pdf-merge` 를 열어봤다

```html
<title>PDF 합치기 — 설치 없이 무료로 여러 PDF 하나로 병합 | ThisIsMyPDF</title>
<meta name="description" content="여러 PDF 파일을 원하는 순서로 하나로 합치는 무료 도구. 서버 업로드 없이…">
<h1 class="page-title">PDF 합치기<span class="privacy-badge">🔒 서버 업로드 없음</span></h1>
<p class="page-sub">여러 PDF 파일을 원하는 순서로 하나로 병합합니다. 설치·가입·용량제한 없이 무료.</p>
+ canonical, hreflang(ko/en/x-default), og:*, WebApplication·FAQPage 구조화 데이터
```

> **기본 세팅은 이미 되어 있다.** 여기서 더 넣을 태그는 없다.
> 문제는 태그가 아니라 **무엇을 조준했는가**다.

### 빠진 것 4개

| # | 빠진 것 | 왜 문제인가 |
|---|---|---|
| **①** | **빈 자리 키워드로 조준이 안 됐다** | 지금 조준은 `PDF 합치기` — 상업 페이지로 꽉 찬 **포화 키워드**다(6~18개월 싸움). 정작 우리만 쓸 수 있는 **`PDF 업로드 없이 합치기` / `서버에 안 올리고 PDF 합치기`** 같은 어구는 title·h1·첫 문단에 **검색되는 형태로 들어가 있지 않다.** h1의 "서버 업로드 없음"은 `<span>` 배지라 어구가 끊긴다 |
| **②** | **HowTo 구조화 데이터가 없다** | 본문에 "사용 방법" h2가 있는데 schema에는 `WebApplication`·`FAQPage`만 있다. **Thunderbit가 먹은 자리가 정확히 "~하는 방법"**이다 |
| **③** | **Search Console 미등록** | 어떤 키워드로 몇 위에 걸려 있는지 **데이터가 0**이다. 지금은 조준을 추측으로 하고 있다 |
| **④** | **페이지↔키워드 매핑이 정의된 곳이 없다** | 도구 40개 × 2언어인데 어느 페이지가 어느 키워드를 담당하는지 문서가 없다 → **자기잠식(cannibalization)** 위험. 예: `pdf-compress`와 `pdf-merge`가 "PDF 용량" 키워드를 두고 서로 순위를 깎는다 |

**④가 가장 근본적이다.** 매핑이 없으면 개별 페이지를 고쳐도 서로 부딪힌다.

## 2. 그래서 "키워드 세팅"의 실제 작업은 4단계다

### 1단계 — 페이지↔키워드 매핑표를 만든다 (문서 작업, 코드 아님)

원칙:
- **1페이지 = 1 주력 키워드.** 예외 없음
- 보조 키워드는 **2~3개까지**, 그리고 **h2·FAQ 질문문에만** 넣는다 (본문에 억지로 반복하지 않음)
- 같은 키워드를 두 페이지가 담당하지 않는다 (④ 방지)

| 페이지 | 주력 (빈 자리 후보) | 보조 (h2·FAQ에) |
|---|---|---|
| `ko/pdf-merge` | **PDF 업로드 없이 합치기** | 여러 PDF 하나로, PDF 병합 순서 지정 |
| `ko/pdf-compress` | **서버에 안 올리고 PDF 용량 줄이기** | PDF 압축 안 될 때, 이미 압축된 PDF |
| `ko/img-blind` | **브라우저에서 이미지 개인정보 가리기** | 사진 얼굴 가리기, 주민번호 마스킹 |
| `ko/pdf-sign` | **PDF 서명 업로드 없이** | 전자서명 이미지 삽입 |
| (오프라인 번들 랜딩) | **폐쇄망 PDF 도구** / **망분리 이미지 편집** | 내부망 문서 도구 |

마지막 줄은 SEO와 **B2B 구매의도가 겹치는 자리**다 — 앞선 광고 문서의 롱테일 키워드와 같은 어구다.
**유료광고와 자연검색을 같은 키워드로 맞추면 검증이 두 배로 빨라진다.**

### 2단계 — 정한 키워드를 세 곳에 심는다

`ko/pdf-merge`를 예로, 지금 → 바꿀 것:

| 위치 | 지금 | 바꿀 형태 |
|---|---|---|
| `<title>` | PDF 합치기 — 설치 없이 무료로 여러 PDF 하나로 병합 | **PDF 업로드 없이 합치기** — 서버 전송 없는 무료 PDF 병합 |
| `<h1>` | PDF 합치기 + 배지 | **PDF 업로드 없이 합치기** (배지는 h1 밖으로 빼서 어구가 끊기지 않게) |
| 첫 문단 | 여러 PDF 파일을 원하는 순서로… | **"파일을 서버에 업로드하지 않고 여러 PDF를 하나로 합칩니다.** 브라우저 안에서만 처리되므로 계약서·증명서도 안전합니다. 개발자도구 네트워크 탭을 열면 외부 요청이 0건인 것을 확인할 수 있습니다." |

첫 문단이 이 형태여야 하는 이유는 두 개다:
1. **첫 100단어 직답**이라 AI 개요 인용 조건에 맞는다
2. **"확인하는 방법"까지 적혀 있어 검증 가능하다** — 남이 블로그에 인용하고 싶어지는 문장이다

> **주의: 키워드를 억지로 반복하지 않는다.** 위 문단에 "PDF 업로드 없이"가 한 번만 나온다.
> 그게 맞다. 반복은 스터핑이고 역효과다.

### 3단계 — HowTo 구조화 데이터를 붙인다 (②)

본문의 "사용 방법" 단계를 `HowTo` 스키마로 표시한다.
`WebApplication` + `FAQPage` + **`HowTo`** 3종이 되면 "~하는 방법" 질의에서 유리해진다.

### 4단계 — Search Console 등록 후, 데이터로 매핑표를 고친다 (③)

**여기서 성격이 바뀐다.** 1~3단계는 추측이고, 4단계부터는 측정이다.

- 등록 → 2~4주 후 **검색어 보고서**를 본다
- 우리가 **11~30위에 걸려 있는 키워드**가 가장 값진 발견이다. 이미 인식됐다는 뜻이므로
  title·첫 문단만 그 어구로 고치면 1페이지로 올라갈 확률이 높다
- 예상 못 한 키워드로 걸려 있으면 **매핑표를 그쪽으로 바꾼다.** 우리 취향보다 데이터가 옳다

## 3. 키워드를 고르는 방법 (전부 무료)

| 방법 | 얻는 것 | 비고 |
|---|---|---|
| **구글 자동완성** | 실제로 많이 치는 어구 | 검색창에 "PDF 합치기 "까지 치고 뜨는 목록 |
| **관련검색어 / People Also Ask** | 주변 어구, 질문형 문장 | somoon 캡처 하단의 "채용공고 크롤링" 같은 것 |
| **네이버 검색광고 키워드도구** | **실제 검색량 숫자** | 광고 계정 필요(무료). **앞선 광고 문서에서 만들자고 한 계정과 동일** → 하나로 처리 가능 |
| **Search Console 검색어 보고서** | **우리 실측 순위·노출** | 등록 후 최고의 소스 |
| **빈 자리 판별** | 그 키워드를 지금 노릴 수 있는지 | 1페이지에 상업 페이지가 거의 없으면 열려 있다 |

### ⚠️ 제 한계를 밝혀둔다

**제 검색 도구는 미국 기준으로 동작해서 한국 구글 SERP를 그대로 재현하지 못한다.**
따라서 **"빈 자리인지"의 최종 판별은 대표님이 직접 검색해 보시거나 Search Console 데이터로 해야 정확하다.**
제가 하는 후보 선정은 어구 발상과 구조 설계까지이고, 검색량·경쟁 확인은 위 두 소스가 정본이다.
(추측을 데이터처럼 쓰지 않기 위해 명시한다.)

## 4. 하지 말 것

| 금지 | 이유 |
|---|---|
| `<meta name="keywords">` 추가 | 구글이 무시한다. 시간 낭비 |
| 키워드 반복(스터핑) | 역효과. 한 문단에 한 번이면 충분 |
| 같은 키워드를 여러 페이지에 | 자기잠식 — 우리끼리 순위를 깎는다 |
| URL을 한글 slug로 변경 | 이득보다 변경 비용(색인·링크 유실)이 크다. **영문 slug 유지** |
| 포화 키워드에 자원 집중 | "PDF 합치기"는 6~18개월 싸움. **빈 자리 40개를 먼저 먹는다** |
| 같은 글을 키워드만 바꿔 복제 | Google *scaled content abuse* 정책 위반. **기능이 다른 도구만 늘린다** |

## 5. 제가 바로 할 수 있는 것 / 대표님이 해주실 것

**제가 할 것** (지시 주시면)
1. **도구 40개 × 2언어 페이지↔키워드 매핑표** 작성 (1주력 + 보조 2~3, 자기잠식 검사 포함)
2. 상위 8~10개 도구부터 **title · h1 · 첫 문단**을 매핑에 맞게 수정 (h1 배지 분리 포함)
3. **HowTo 구조화 데이터** 전 도구 적용
4. Search Console **인증 메타태그 주입** + 사이트맵 제출 준비

**대표님만 가능**
| 항목 | 이유 |
|---|---|
| Search Console 속성 생성 → **인증용 HTML 태그 값 전달** | 계정 소유자 |
| 네이버 검색광고 계정(키워드도구용) | 본인 인증 — **광고 집행 계정과 동일** |
| 후보 키워드 몇 개를 **한국 구글에서 직접 검색해 1페이지 확인** | 제 도구의 지역 한계(3절) |
