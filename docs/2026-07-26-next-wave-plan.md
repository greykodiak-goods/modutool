## 1. 신규 기능 — A안: 변환 매트릭스 (Convert Matrix) ★최대 레버

**아이디어**: 지금 벤더링된 엔진만으로 "A → B 포맷 변환" 페이지를 **조합으로** 생산한다.
전 세계 검색량 최상위 쿼리가 정확히 이 형태다: `mov to mp4`, `webp to png`, `m4a to mp3`, `png to jpg`, `mkv to mp4`…

| 축 | 조합 | 엔진 |
|---|---|---|
| 영상 | mov·mkv·avi·webm → mp4 / mp4 → webm | ffmpeg (이미 있음) |
| 오디오 | m4a·wav·ogg·aac → mp3 / mp3 → wav | ffmpeg |
| 영상→오디오 | mp4·mov → mp3·wav | ffmpeg |
| 이미지 | webp·png·bmp → jpg / jpg·webp → png / → webp | canvas (이미 있음) |

**왜 강력한가**: 페이지 1개 = 고유 키워드 1개인데, 제작 한계비용은 템플릿 + 매트릭스 정의뿐. 언어팩까지 곱하면 노출면이 급증한다.

**⚠️ 정직한 리스크 — 이게 이 전략의 핵심 판단**:
구글은 실질 가치 없이 템플릿만 찍어낸 페이지를 **doorway/thin content로 강등**한다. 단순 자동생성은 역효과다.
→ **원칙: 각 페이지는 (a) 실제로 동작하는 도구 + (b) 그 조합에만 해당하는 고유 콘텐츠를 가져야 한다.**
포맷별 고유 콘텐츠 예: "왜 MOV가 윈도우에서 안 열리는가", "WebP를 JPG로 바꾸면 투명도가 사라진다", "M4A→MP3는 재인코딩이라 손실이 한 번 더 생긴다".
→ 이 고유 문단을 못 쓰는 조합은 **만들지 않는다.** 1차는 검색량 상위 **12조합**으로 제한하고, 색인·순위를 확인한 뒤 확장 여부를 결정한다(무한 생성 금지).

**구현 방식**: `convert-matrix.json`(조합 + 포맷별 고유 문단) + 빌드 스크립트가 en/ko 페이지 생성. 툴 로직은 기존 엔진 재사용.

## 2. 신규 기능 — B안: 오프라인 PWA ★경쟁 불가 차별점

전 도구가 이미 클라이언트 처리다 → **서비스워커만 붙이면 인터넷 없이 전체 사이트가 동작**한다.
업로드형 경쟁사는 원리상 절대 따라올 수 없다. "비행기에서, 지하철에서, 사내망에서 쓰는 PDF·영상 도구."

- 홈 화면 추가(설치형) → 재방문 채널 확보(광고 노출의 반복성).
- 31MB ffmpeg·13MB opencv 엔진 캐시를 **명시적으로 관리**(사용자가 "엔진 미리 받기" 선택 가능 → 첫 사용 체감 개선).
- Product Hunt / Show HN 런칭 앵글로 최상급: "No upload. Now also no internet."
- 주의: 캐시 무효화 전략을 잘못 짜면 사용자가 옛 버전에 갇힌다 → 버전 기반 캐시 + 갱신 감지 배너 필수.

## 3. 신규 기능 — C안: 수요검증 루프 (이번에 가능해짐)

방금 만든 `dailyStats` 롤업이 **도구별 일별 사용량**을 정확히 쌓는다. 이걸 의사결정에 건다:
- 월 1회 백오피스 리뷰 → **상위 20%는 심화**(옵션 추가·품질 개선), **하위 20%는 통폐합**.
- 실패 사유 상위 항목 = 다음 스프린트 백로그(이미 구조 있음).
- 유입 출처(ref) 상위 = 마케팅 재투자 지점.
→ 기능을 감으로 늘리지 않고 **데이터로 늘린다**. 40개에서 더 늘릴수록 이 루프가 중요해진다.

## 4. 수익화 전략 갱신 — 영상이 판을 바꾼다

기존 계획(AdSense 글로벌 + AdFit 국내, 상/하 슬롯)은 유지하되, **영상 도구는 성격이 다르다**:

- PDF·이미지 도구는 처리가 즉시라 광고 체류가 짧다. **영상은 인코딩에 수십 초~수 분이 걸린다** — 사이트에서 유일하게 "정당한 대기 시간"이 있는 구간.
- 이 대기 화면이 **가장 가치 있는 광고 지면**이다(체류시간 = 뷰어빌리티 = CPM).
- **철칙**: 처리 버튼과 광고 사이에 충분한 거리. 오클릭 유도는 정책 위반이자 신뢰 훼손 — 절대 금지.
- 영상 카테고리는 CPM도 상대적으로 높다 → **AdSense 승인 후 영상 페이지부터 슬롯 활성화**하고 성과를 측정한 뒤 전 사이트 확대.

**손익 감각(기존 유지)**: RPM $2~8 → 일 1만 PV면 월 $600~2,400. 변환 매트릭스+언어팩이 PV를 만드는 엔진.

## 6. 막힌 것 — 레포 시크릿 1개 (반복 확인됨)

`convex-deploy` 워크플로가 **DOPPLER_TOKEN·CONVEX_DEPLOY_KEY 둘 다 빈 값**으로 4회 실패.
- 컨테이너에서 convex.dev 전 호스트가 차단돼(실측 000) 배포는 러너 경유가 유일.
- GitHub 시크릿 **생성 API는 이 연동에 없어** 내가 등록할 수 없음(확인 완료).
- ops 레포의 `DOPPLER_TOKEN`은 계정이 조직이 아니라 **레포 간 공유가 안 됨**.

→ https://github.com/greykodiak-goods/modutool/settings/secrets/actions
→ **New repository secret** → Name `DOPPLER_TOKEN` (ops와 동일 토큰) → 저장.
→ Doppler에 `CONVEX_DEPLOY_KEY` 등록. **이 토큰 하나면 이후 구글 OAuth·애드센스 ID까지 전부 Doppler에서 조달**되어 레포별 시크릿 등록이 영구히 사라진다.
(급하면 대안: 같은 화면에서 `CONVEX_DEPLOY_KEY`를 직접 등록해도 폴백 경로로 즉시 동작.)
